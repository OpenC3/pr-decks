PR #4052 LATEST Handling
OpenC3/cosmos · PR #4052 · Open

LATEST works wherever it can, and fails clearly where it can't

LATEST resolves an item to whichever packet received it most recently. Several APIs ignored that, resolved it against the wrong scope or time, or accepted it where it can't name a packet. This PR fixes each case in Ruby and Python.

History asks which packet was newest then

The packet newest now may not have been newest at start_time. Each candidate is now queried with its PACKET_TIMESECONDS and the newest wins. Ranges do the same row by row.
